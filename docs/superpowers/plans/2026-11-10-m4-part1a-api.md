# M4 part 1a: the API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The router serves its API on the LAN: an HTTPS listener with a self-made certificate, a first password and sessions, the router's state, counters and events over a WebSocket envelope and over gRPC, with a placeholder page where the panel will be.

**Architecture:** A new crate `openfeo-api` holds the listener, authentication, the envelope and the services; its decisions are small sans-IO cores (certificate, backoff, sessions, gate, envelope) with thin tokio drivers over them. What the API reports is derived, not collected: the World gains three facts (addresses, link speed, WAN status), `openfeo-reconcile` gains pure views (`wan::phase`, `derive::derive`, `state::state`), and the World's publisher runs the derive step on every publish so no change is skipped. Counters stay out of the World and are read only while someone is subscribed.

**Tech Stack:** Rust stable 2024; `hyper` 1, `tonic` (the release that matches the workspace's `prost` 0.14), `axum` for routing and the WebSocket upgrade, `rustls` with `ring` through `tokio-rustls`, `rcgen`, `argon2`, `sha2`, `toml_edit`; `x509-parser` in tests only. Versions are settled in Task 2 and must pass `cargo deny`.

**Spec:** `docs/superpowers/specs/2026-11-10-m4-api-and-panel-design.md` (the "Part 1" sections; this plan is part 1a, everything in Rust). SPEC §6.2, §8.1 to §8.3, §9, §10, §12 (the M4 row), §13.

**Not in this plan (part 1b):** `web/` (client, components, panel), embedding the panel and `OPENFEO_PANEL_DIST`, `/licences.txt`, Playwright, the client's own tests, `make run PANEL=` and the `openfeo.panel_host=` knob, Node in CI, ADR for the web build.

## Global Constraints

- Every source file starts with `// SPDX-License-Identifier: GPL-2.0-or-later` and `// Copyright (C) 2026 Andrew Newton` (`#` in TOML and sh; `//` in `.proto`).
- Documentation ranges only in tests, fixtures and docs: `203.0.113.0/24`, `198.51.100.0/24`, `192.0.2.0/24`, `2001:db8::/32`, ULA `fd12:3456:789a::/48`; LANs are RFC 1918 as the fixtures already have them. The test password is `lab-admin-password` and nothing else.
- `clippy -D warnings` with pedantic; no `unwrap`/`expect` outside tests; `thiserror` in libraries, `anyhow` only in `crates/openfeo` and `harness/`; no `std::process::Command` outside `harness/`.
- `openfeo-api` is not a kernel-facing crate: no direct `libc`, `nix` or netlink dependency (`scripts/check-deps.sh`). `openfeo-reconcile` and `openfeo-world` stay pure: no tokio in their trees. `openfeo-config` gains no `tonic`, `hyper` or `tokio`.
- `#![forbid(unsafe_code)]` in `openfeo-api`.
- No OpenSSL and no `aws-lc`: rustls, tokio-rustls and rcgen are built with their `ring` features and default features off.
- A password, a token or a password hash never reaches a log line, an error message or a `Debug` output. Types that hold one implement `Debug` by hand.
- Every timer in authentication (session idle, backoff) runs on the monotonic clock, never the wall clock: SNTP may step the wall clock by years after boot.
- The numbers are the design's: 12 to 256 characters; Argon2id 19456 KiB, 2 passes, 1 lane; backoff 1 s doubling to 300 s, forgotten after 900 s, 1024 sources, a source is an IPv4 address or an IPv6 /64; 16 sessions, idle 1800 s; first frame within 5 s; frames up to 1 MiB; 16 sockets, 16 subscriptions each; event queue 256; ping every 20 s; certificate 825 days, reissued under 60.
- Console lines are a contract: each new line gets a line in a contract test in the module that prints it.
- Cargo needs `OPENFEO_NFT_SRC=$PWD/build/nft/src OPENFEO_UAPI_INCLUDE=$PWD/build/kernel/headers/include` for anything that builds `openfeo-nft` (`-p openfeo`, `-p openfeo-harness`, `--workspace`); the QEMU suites also need `OPENFEO_KERNEL=$PWD/build/bzImage` and a fresh `make kernel`.
- Two messages called `Event` and two enums called `WanPhase` exist: the plain ones in `openfeo-world` (facts) and the protobuf ones in `openfeo_config::{events, state}` (the wire). Code that sees both imports the protobuf ones as `pb::…`. The tests below that read a `State` mean the protobuf enum.
- A helper a test below calls and no task defines (`cache_with`, `stamped`, `world()`, `authed()`, `spawn_api`, …) is that test module's own to write, as small as the test needs.
- Commits `git commit -s`, identity `Andrew Newton <andy@vitri.ltd>`, subject `<area>: <summary>`. Nothing is pushed and no PR opened without a sweep (standing word of 2026-11-07); never merged.

## Review Focus

1. **A client that stalls**: a TCP connection that never finishes its TLS handshake, or a socket that stops reading. It must not hold a slot for ever or delay anyone else. Pinned by `a_handshake_that_never_finishes_is_dropped_and_frees_its_slot` (Task 14) and `a_socket_that_stops_reading_is_closed_not_waited_on` (Task 15).
2. **The wall clock stepping** by years when SNTP first answers. Sessions must not all lapse and backoff must not reset or lock. Pinned by `sessions_and_backoff_take_only_the_monotonic_clock` (Task 10: the cores take `now_ms` and nothing else) and `a_certificate_issued_on_a_guess_is_reissued_once_the_clock_is_right` (Task 9).
3. **Hostile input before login**: a 10 MiB body to `/api/login`, a 300-character password, bytes that are not UTF-8, a `ClientMsg` that is not protobuf. Refused cheaply, with no Argon2 run. Pinned by `an_oversized_body_is_refused_before_it_is_read` (Task 14), `a_password_outside_12_to_256_characters_is_refused_without_hashing` (Task 10) and the envelope fuzz target (Task 17).
4. **Two clients setting the first password at once**: exactly one wins and the file holds the winner's hash. Pinned by `two_first_passwords_at_once_and_exactly_one_wins` (Task 14).
5. **An IPv4 client seen as `::ffff:a.b.c.d`** on the dual-stack listener: it is the same LAN client and the same backoff source as its IPv4 form. Pinned by `an_ipv4_mapped_peer_is_its_ipv4_self` (Task 11) and `backoff_keys_a_mapped_address_as_ipv4_and_an_ipv6_client_by_its_64` (Task 10).

### Task 5: What up means, and the events, as pure functions

**Files:**
- Create: `crates/openfeo-reconcile/src/wan.rs`, `crates/openfeo-reconcile/src/derive.rs`
- Modify: `crates/openfeo-reconcile/src/lib.rs`, `src/fixtures.rs`

**Interfaces:**
- Consumes: Task 4's facts; `wan_netdev(&Wan)`, `wan_ifname(&Wan)`, `bridge_name(&str)`; the fixtures `dhcp_world`, `dhcp_world_without_lease`, `static_world`, `pppoe_world`, `pppoe_world_without_link`, `static_world_with_leases`, `pd_world`.
- Produces:
  ```rust
  pub fn wan::phase(world: &World, wan: &Wan) -> WanPhase
  pub fn wan::reason(world: &World, wan: &Wan) -> String   // "" when up; "no carrier" without carrier; else the status fact's cause, or ""
  pub fn derive::derive(prev: &World, next: &mut World, boot_ms: u64) -> Vec<EventDraft>
  ```
- `phase`: the design's table. Carrier is the carrier of the WAN's port link (the VLAN sub-interface when tagged). Static: `Up` with carrier and the configured address in `world.addresses` on `wan_netdev`. DHCP: `Up` with carrier and `world.dhcp4[name]`; `Connecting` with carrier alone. PPPoE: `Up` with `world.pppoe[name].ipv4` present; `Connecting` with carrier and no such session. No carrier: `Down`.
- `derive` first brings `next.wan_status` up to date (an entry per configured WAN; a changed phase sets `since_boot_ms = boot_ms`; reaching `Up` clears `cause`; entries for WANs no longer configured go), then returns, WANs in config order and then LANs:

  | Change from `prev` to `next` | Topic | Fields |
  |---|---|---|
  | phase leaves `Up` | `wan.<name>.down` | `reason` (as `wan::reason` on `next`) |
  | phase reaches `Up` | `wan.<name>.up` | none |
  | the WAN's IPv4 address differs (lease address, PPP local) | `wan.<name>.addr` | `address`, `change` = `added` or `withdrawn` |
  | a delegated prefix appears or goes (`dhcp6[name]`) | `wan.<name>.prefix` | `prefix`, `change` |
  | a lease's MAC appears in `leases[lan]` | `lan.<name>.lease.granted` | `address`, `mac`, `host` (empty if none) |
  | a lease's MAC goes | `lan.<name>.lease.released` | `address`, `mac`, `host` |

  ```rust
      pub fn check(&mut self, token: &str, now_ms: u64) -> bool            // true also refreshes last-seen
      pub fn is_live(&self, token: &str) -> bool                           // no refresh: what an open socket asks after any revocation
      pub fn connected(&mut self, token: &str, delta: i32)                 // a WebSocket opened (+1) or closed (-1)
      pub fn revoke(&mut self, token: &str) -> bool
      pub fn revoke_others(&mut self, keep: &str) -> usize
      pub fn sweep(&mut self, now_ms: u64) -> Vec<[u8; 32]>                // lapsed hashes: idle over SESSION_IDLE_MS and no socket
      pub fn len(&self) -> usize
  }
  ```
- `Verifier` runs Argon2 on the blocking pool behind a one-permit semaphore.
- `Backoff::failed`: the n-th consecutive failure sets the wait to `min(1000 << (n-1), 300_000)` ms from `now_ms`; an entry whose last failure is over 900 000 ms old is forgotten; at 1024 sources the entry with the oldest last failure goes.
- `Sessions::issue` at the cap drops the session idle longest, one with no socket before one with.

  ```rust
  pub trait Backend {                                             // the two things a connection needs at once
      fn authenticate(&mut self, token: &str) -> bool;
      fn backlog(&mut self, n: u32) -> Vec<Event>;                // the last n events, oldest first (protobuf Events)
  }
  #[derive(Debug, PartialEq)]
  pub enum Out {
      Send(ServerMsg),
      Ask { id: u32, request: Request },                          // the driver performs it (it may hash a password) and calls reply()
      Close(u16),                                                 // 4401: no or bad auth; 1009: too big; 1003: text frame
  }
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
  pub enum Topic { State, Counters, Events }
  pub struct Conn { /* authed, subscriptions, the outbox */ }
  impl Conn {
      pub fn new() -> Self
      pub fn on_binary(&mut self, frame: &[u8], backend: &mut dyn Backend) -> Vec<Out>
      pub fn on_text(&mut self) -> Vec<Out>
      pub fn on_auth_deadline(&mut self) -> Vec<Out>              // Close(4401) unless authenticated
      pub fn reply(&mut self, id: u32, result: Result<Response, Error>)   // the answer to an Ask, queued ahead of pushes
      pub fn wants(&self, topic: Topic) -> bool
      pub fn push_state(&mut self, state: &State)                 // coalesced
      pub fn push_counters(&mut self, counters: &Counters)        // coalesced
      pub fn push_event(&mut self, event: &Event)                 // queued, EVENT_QUEUE deep
      pub fn next_out(&mut self) -> Option<ServerMsg>             // what the writer sends next: replies first, then pushes
      pub fn authenticated(&self) -> bool
  }
  ```
- Rules: the first frame must be `Auth`; a good token is answered with an empty `Response` under the frame's `id`, anything else with `Error { UNAUTHENTICATED }` then `Close(4401)`. A frame that does not decode, or carries no body: `Error { INVALID_ARGUMENT }` with `id` 0, connection kept. A frame over `MAX_FRAME`: `Close(1009)`. `Subscribe` to an unknown topic: `Error { NOT_FOUND }`; a 17th subscription: `Error { RESOURCE_EXHAUSTED }`; subscribing twice is harmless. `Subscribe { topic: "events", backlog: n }` queues the backend's last `min(n, 256)` first. Pushes have `id` 0. When the event queue is full the oldest queued event is dropped and one `Error { DATA_LOSS }` push is queued ahead of the rest (not one per drop).
