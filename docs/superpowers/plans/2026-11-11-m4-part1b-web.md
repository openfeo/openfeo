# M4 part 1b: the web workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A booted router serves its real panel: a JavaScript client for the API, the design system as a component package, and three screens (set the admin password, log in, a live read-only dashboard), embedded in the binary and proven by Playwright from the lab's LAN side.

**Architecture:** `web/` is an npm workspace of three packages: `@openfeo/client` (the wire, no Vue), `@openfeo/ui` (the look, no API) and `panel` (the app that joins them). `make panel` builds it into `$(BUILD)/panel`; `openfeo-api`'s `build.rs` turns that directory into a table of embedded files when `OPENFEO_PANEL_DIST` names it, and serves a placeholder when it does not, so cargo never runs npm. The harness runs the client's own tests and a Playwright run inside the LAN namespace against the VM.

**Tech Stack:** Node 22, npm workspaces; TypeScript 6.0 (not 7: `typescript-eslint` 8 accepts `<6.1.0`); `@bufbuild/protobuf` and `@bufbuild/protoc-gen-es` 2.17; Vue 3.5, `vue-router` 5, Vite 8, `@vitejs/plugin-vue` 6; `vitest` 5, `@vue/test-utils` 2.5, `happy-dom` 21; ESLint 10 with `typescript-eslint` 8 and `eslint-plugin-vue` 10; `@playwright/test` 1.65 (Chromium); `lucide-static` 1.72 (ISC). Rust side: `flate2` (already in `Cargo.lock`) and `sha2` in `openfeo-api`.

**Spec:** `docs/superpowers/specs/2026-11-10-m4-api-and-panel-design.md` (sections "The shape of M4", "The client", "The components", "The panel", "Looking at the real panel", "Build and CI", "Harness and tests", and "After part 1a"). `SPEC.md` §8, §9, §11, §13, §14.

## Global Constraints

- **Cargo never runs npm.** `cargo build`, `cargo test` and `cargo clippy` need no Node and embed the placeholder. `OPENFEO_PANEL_DIST` is set for the binary's build only (`make bin`), never exported to `make lint` or `make test`.
- **npm installs without scripts:** `npm ci --ignore-scripts`, one lockfile at `web/package-lock.json`, `.nvmrc` says `22`. A version published in the last 7 days is held back to the one before it (`npm view <pkg> time`).
- **The layering rule:** `web/ui` never imports `@openfeo/client`; `web/client` never imports `vue` and uses no DOM beyond `fetch` and `WebSocket`; `web/panel` reaches the generated message code only through `@openfeo/client`, and holds no CSS beyond page layout.
- **`@openfeo/client` has one runtime dependency**, `@bufbuild/protobuf`, runs in current browsers and in Node 22, and holds no global state: two routers, two objects.
- **The page's policy stands as part 1a set it:** `default-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`. So no inline script, no `style="…"` attribute in any template, no `data:` URL (Vite's `build.assetsInlineLimit` is `0`), and nothing is fetched from anywhere but the router.
- **No cookie.** The token lives in `sessionStorage`; the theme (`openfeo.theme`) is the only thing in `localStorage`.
- **The design system is copied, not redrawn.** Its files come from the maintainer's design-system document, whose location is his to give and is not written in this repository.
- **Every string follows the design system's voice:** sentence case, buttons are verbs, units always and with a space (`941.2 Mbit/s`), rates to one decimal, counts as integers, status is a word with a colour, names as the config and the kernel have them (`wan0`, `br-lan0`, `p0`) in mono, no emoji, "OpenFeO" in prose.
- **All of `web/` is GPL-2.0-or-later:** every `.ts`, `.vue`, `.css`, `.mjs`, `.js`, `.html` and `.yaml` file there starts with `SPDX-License-Identifier: GPL-2.0-or-later` and `Copyright (C) 2026 Andrew Newton` in its first three lines; every `package.json` there says `"license": "GPL-2.0-or-later"` and `"private": true`.
- **Bundled npm packages pass `deny.toml`'s accepted licence list;** the two fonts are SIL OFL 1.1 and ship with their licence texts.
- **Rust rules stand:** `clippy -D warnings`, no `unwrap`/`expect` outside tests, no shelling out outside `harness/`, SPDX headers, a fuzz target for every parser, test hooks only under the `harness` feature. A bare cargo call needs `OPENFEO_NFT_SRC=$PWD/build/nft/src OPENFEO_UAPI_INCLUDE=$PWD/build/kernel/headers/include`.
- **Public writing:** documentation address ranges in every example, fixture and test (203.0.113.0/24, 198.51.100.0/24, 192.0.2.0/24, 2001:db8::/32, fd12:3456:789a::/48; RFC 1918 LANs as the fixtures have them).
- **Commits:** `git commit -s`, subject `<area>: <summary>` (`web`, `client`, `ui`, `panel`, `api`, `harness`, `docs`, `ci`).
- Where this plan names an npm tool's option, check the tool's current documentation before relying on memory: Vite 8, `vue-router` 5 and `vitest` 5 are all recent majors.

## Review Focus

What the design implies and a person will meet, most likely first. Each has its test in the task that owns the code.

1. **A connection that dies without saying so** (a laptop that slept, a Wi-Fi drop): the dashboard must say the connection is lost within a minute and stop showing numbers, not freeze on the last ones. The client probes a silent socket (Task 12: `a silent socket is probed and then dropped`; Task 13's lab test with the LAN link cut).
2. **A counter that goes backwards or a link that comes and goes** (a PPP session made anew, an interface re-created): the rate is 0 for that link in that second, never negative and never a spike (Task 12: `a counter that went backwards is a rate of zero`, `a link in only one sample has no rate`).
3. **A tab left open across a router restart or an update:** the old page asks for a file the new binary does not have and must get `404`, not the page's HTML as JavaScript; and the page itself is never used stale (Task 5: `a_missing_asset_is_404_not_the_page`, `a_hashed_file_is_cached_for_good_and_the_page_is_revalidated`). The session is gone too, and the panel must land on the right screen with the reason (Task 14: `after the session ends the screen is chosen again from status`).
4. **An event or an enum value the panel does not know** (a later part's topic, a newer router behind a cached page): shown as the raw topic and its fields in mono, never dropped and never a blank dashboard (Task 15: `an unknown topic is shown as it came`, `an unknown enum value reads as Unknown`).
5. **A password counted differently by the browser and the router:** the router counts characters, so the form counts code points, and it neither trims nor alters what was typed (Task 14: `twelve code points are enough, whatever their bytes`, `the password is sent exactly as typed`).

## Calls this plan makes beyond the design

Each is the author's, with what it costs if wrong.

1. **The status call gains `config_unreadable`** (Task 4). The design's panel shows a screen of its own for a config file that cannot be read, and part 1a's status cannot tell that case from a refused file that still holds a password. Cost: one more field frozen by `buf breaking`.
2. **The client probes a socket that has been silent for 30 s and drops it after 10 s more** (Task 12). The design has the server ping; a browser cannot see those pings, so a connection that dies without a close would freeze the dashboard. Cost: one `GetState` every 30 s on a socket that subscribes to nothing chatty.
3. **After a reconnect, events are subscribed again without a backlog and the listener is told some may be lost;** the panel then asks for its last eight afresh. Events carry no sequence number (issue #71), so a backlog on reconnect would repeat them. Cost: a short flicker of the events list after a drop.
4. **Why a session ended is the client's reading of when the router refused it:** before the `Auth` was acknowledged it is `lapsed`, after it `revoked`. The router does not say which. Cost: a restart of the router process reads as "your session ended", which is true but not the whole story.
5. **The page is answered with `no-cache` and an `ETag`, not `no-store`,** so a reload costs one small request and is never stale. Files are stored gzip-compressed and inflated for a client that does not take gzip. Cost: `flate2` joins the binary.
6. **TypeScript stays on 6.0** until `typescript-eslint` accepts 7. Cost: a later bump.
7. **Node's tests reach the router by its LAN address and accept its certificate unchecked; Chromium reaches it by name through a resolver rule,** not through the router's DNS (the `m4` and `dns` suites already prove that path). Cost: the browser run does not exercise name resolution.
8. **The relay is proven by hand once, and the extra host name by a scenario;** no scenario runs the relay itself, since a suite is already inside the sandbox when it starts and cannot bind in the host's network. Cost: a relay regression shows only when someone uses `make run PANEL=`.
9. **Durations are written `3d 4h`, as the approved screens have them,** though the voice rule puts a space before a unit. Cost: one formatter to change.
10. **`ofo.css` carries the SPDX lines the repository requires;** nothing else in a copied file changes. The website's component guidelines are copied with the panel's; the mark's animation script is not.

  - `pub fn serve(table: &[Asset], method: &Method, path: &str, headers: &HeaderMap) -> Response`

The rules, all of them:
- Types by extension: `.html` `text/html; charset=utf-8`, `.js` `text/javascript`, `.css` `text/css`, `.svg` `image/svg+xml`, `.txt` `text/plain; charset=utf-8`, `.json` `application/json`, `.woff2` `font/woff2`, `.png` `image/png`, `.ico` `image/x-icon`. Anything else fails the build, naming the file.
- `gzip` (best compression) for the first six; the last three are stored as they are.
- `etag` is `"` + the first 16 hex digits of the SHA-256 of the uncompressed bytes + `"`.
- `build_table` walks `dist` without following symlinks; a symlink or anything not a regular file or directory is an error; no `index.html` is an error; more than 8 MiB in all is an error ("that is not a panel"); paths begin with `/` and are sorted.
- `build.rs`: `cargo:rerun-if-env-changed=OPENFEO_PANEL_DIST`; when set, `rerun-if-changed` on the directory, write each body to `OUT_DIR` and a `panel_assets.rs` that `include_bytes!` them; when unset, an empty table.
- `serve`: only `GET` and `HEAD` (else `405` with `Allow: GET, HEAD`). `/` is `/index.html`. A path in the table is that file. A path under `/assets/` not in the table is `404`. Any other path is the page. An empty table serves `PLACEHOLDER_PAGE` in place of the page.
- Headers: `ETag` always; `Cache-Control: public, max-age=31536000, immutable` under `/assets/`, `no-cache` otherwise; `Vary: Accept-Encoding` on a gzip asset; `If-None-Match` naming the tag (alone, in a list, or with `W/`) gets `304` and no body.
- A gzip asset goes out as stored, with `Content-Encoding: gzip`, to a client whose `Accept-Encoding` lists `gzip` or `*` without `q=0`; to any other client it is inflated first. `HEAD` carries the `Content-Length` of what `GET` would send, and no body.

### Task 12: `@openfeo/client`: reconnecting, the watchdog, the session's end, and rates

**Files:**
- Create: `web/client/src/{backoff.ts,rates.ts}`, `web/client/test/{reconnect,rates}.test.ts`
- Modify: `web/client/src/{socket.ts,router.ts,index.ts}`

**Interfaces:**
- Produces: `export interface LinkRate { name: string; rxBitsPerSec: number; txBitsPerSec: number }`; `export function rates(previous: Counters, next: Counters): LinkRate[]`.
- Produces (`backoff.ts`, internal): `delayMs(attempt: number, random: number): number` — `min(10000, 500 × 2^attempt)` scaled by `0.5 + random / 2`; the attempt count returns to 0 once an `Auth` is acknowledged.

The behaviour, all of it:
- A socket that closes while anything is subscribed or waiting: the connection is `reconnecting`; what was waiting is rejected `UNAVAILABLE` (a request is never sent twice); after the delay a new socket authenticates and subscribes each topic again. `events` is subscribed again with no backlog and its `onLost` is called, since events may have passed meanwhile.
- Close code 4401: the session is over. Before the `Auth` was acknowledged the reason is `lapsed`; after it, `revoked`; after this router's own `logout()`, `logout`. The store is cleared, every subscription is closed, the connection is `idle`, and nothing reconnects.
- Close code 1013 (no place free) and every other code: a drop, reconnected as above.
- A frame that is not a `ServerMsg`: the socket is closed and treated as a drop.
- The watchdog: while open, when nothing has arrived for `probeAfterMs` a `GetStateRequest` is sent; when nothing at all arrives within `probeTimeoutMs` of that, the socket is closed and treated as a drop. Any frame resets it.
- `rates`: the time between the samples is `next.monotonicMs - previous.monotonicMs`; zero or less gives `[]`. A link in both samples gets `(bytes_next - bytes_previous) × 8000 / ms` each way, and `0` where the counter went backwards. A link in only one sample is left out.
